# EU Resilience Desk frontend

A no-build browser interface and Python API for the `eu-resilience-agent`.
Everything in this application lives under `frontend/`; the repository's
`backend/` is not used or modified.

## Run locally

From the repository root, inject the selected Azure Developer CLI environment
and start the server:

```bash
azd exec -- env PYTHONPATH=src .venv/bin/python frontend/server.py --port 4173
```

Open <http://127.0.0.1:4173>. The API uses `DefaultAzureCredential`, resolves
the latest `eu-resilience-agent` version, retains its last response ID per
browser session, and executes the agent's requested Python functions locally.

If `azd` is unavailable, authenticate with `az login`, export the project
endpoint directly, and run the same server:

```bash
export AZURE_AI_PROJECT_ENDPOINT="https://<account>.services.ai.azure.com/api/projects/<project>"
PYTHONPATH=src .venv/bin/python frontend/server.py --port 4173
```

The agent must already be created. Its creation script also expects
`AZURE_TOOLBOX_CONNECTION_ID` to identify a remote-tool connection targeting:

```text
${AZURE_AI_PROJECT_ENDPOINT}/toolboxes/eu-resilience-skills/mcp?api-version=v1
```

The connection should use a user Entra token with audience
`https://ai.azure.com`. Once that connection exists, create or update the agent
with:

```bash
azd exec -- env PYTHONPATH=src .venv/bin/python \
  src/agents/eu-resilience-agent/create_eu_resilience_agent.py
```

## API

- `GET /api/health` reports local configuration readiness.
- `POST /api/chat` accepts `message`, optional `sessionId`, and the guarded
  `approveCoordinationCase` flag.
- `POST /api/session/reset` clears the server-side response context.

Case creation requires the exact approval instruction generated by the UI,
an existing session, and an explicit review checkbox. The API permits at most
one `open_coordination_case` attempt for that approval request.
