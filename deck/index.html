Building block · 4 of 5

Skills — reusable behavior

As agents grow, teams accumulate behavioral guidelines that must stay consistent across every conversation. Embedding them in each prompt creates duplication.

🧩 The problem

An escalation policy, a review checklist, messaging rules — copied into many agents. Change one rule → edit and redeploy them all.

📜 The fix: Skills

Author a SKILL.md once, store it centrally & versioned in Foundry, and deliver it to any agent. Update = new version, promote to default — no agent code changes.

✅ Consistent across conversations 🗂️ Versioned & immutable ♻️ Reused across agents 🧭 Follows the Agent Skills spec

Source: Use skills with Microsoft Foundry agents (preview)

Building block · 4 of 5

Anatomy of a SKILL.md

YAML front matter (name, description) + a Markdown body that becomes injected instructions.

---
name: pto-accrual-policy
description: Compute PTO balances,
  accrual, and proration consistently.
---

# PTO accrual policy

Apply these rules whenever a user
asks about vacation, PTO, or leave.

## Instructions
- Accrual is monthly: 1.5 days per
  completed month of service.
- Prorate the first & last month.
- Never let a balance go negative.
- Show the calculation step by step.

🔤 name

URL-path key. Lowercase, digits, hyphens — pattern ^[a-z0-9]([a-z0-9\-]*[a-z0-9])?$, unquoted.

📝 description

One-liner shown in skill listings (≤ 1,024 chars, unquoted).

📄 Body

Free Markdown → becomes the skill's injected instructions.

Each skill lives in its own subdir: skills/pto-accrual-policy/SKILL.md.

Building block · 4 of 5

Two ways to deliver a skill

💉 Direct injection

Download the SKILL.md into the agent project; its content is added as extra system instructions at session start. Works without a toolbox.

🧰 Attach to a toolbox

Expose skills over one MCP endpoint. Any MCP client discovers them and loads the full body only when needed (progressive disclosure).

In Cosmopilot: src/skills.py zips each skills/*/SKILL.md and registers it as a versioned Foundry skill (project.beta.skills), promoting each new version to default. The HR agent also injects both skill bodies into its prompt at create time — so guidelines take effect even before the preview API is reached.

Versioning: every update is an immutable SkillVersion; the parent skill tracks default_version. Requires the Foundry User role + a public endpoint.

Evaluator deep dive · Quality

General-purpose evaluators

Writing quality independent of factual correctness. Both use an LLM judge.

builtin.coherence

Coherence

query, response · 1–5 · pass ≥ 3

Measures logical order, clear connections, transitions, and whether the response forms an understandable train of thought.

Example: “Renewables cut emissions, then lower fuel costs, so they improve both climate and energy independence.” → 4/5, pass.
builtin.fluency

Fluency

response · 1–5 · pass ≥ 3

Measures grammar, vocabulary, sentence construction, readability, and how smoothly ideas are communicated.

Example: “Plants convert sunlight, water, and carbon dioxide into glucose and oxygen.” → 5/5, pass.

Scores in examples are illustrative. Judge-model choice and threshold configuration can change results.

Microsoft Learn: General-purpose evaluators

Evaluator deep dive · Text similarity

Meaning, tokens, and n-grams

Compare a generated response with an expected ground_truth.

builtin.similarity

Similarity

query, response, ground_truth · 1–5 · pass ≥ 3

An LLM judge checks semantic equivalence, so paraphrases can score well even without exact word overlap.

Example: “Returns are accepted for 30 days” vs “You have one month to return it.” → 4/5.
builtin.f1_score

F1 Score

response, ground_truth · 0–1 · pass ≥ 0.5

Harmonic mean of token precision and recall. It rewards shared words and penalizes both extras and omissions.

Example: “Open from 9 to 6” vs “The store is open 9am–6pm.” → partial overlap, ≈ 0.5.
builtin.bleu_score

BLEU

response, ground_truth · 0–1 · pass ≥ 0.5

Measures matching n-grams, traditionally for machine translation where wording and phrase order matter.

Example: Reference “The cat sits on the mat”; identical translation → near 1.0.

Microsoft Learn: Textual similarity evaluators

Evaluator deep dive · Text similarity

Sentence and summary metrics

Deterministic metrics are cheap and reproducible, but measure overlap rather than truth.

builtin.gleu_score

GLEU

response, ground_truth · 0–1 · pass ≥ 0.5

Google-BLEU balances n-gram precision and recall per sentence, making short sentence comparisons less corpus-dependent.

Example: “She goes to school” vs “She goes school” → one missing token, partial score.
builtin.rouge_score

ROUGE

response, ground_truth + rouge_type · 3 × 0–1

Recall-oriented overlap for summaries. Returns separate precision, recall, and F1; each defaults to threshold 0.5.

Example: Reference mentions flooding + outages; summary mentions only flooding → high precision, lower recall.
builtin.meteor_score

METEOR

response, ground_truth · 0–1 · pass ≥ 0.5

Aligns tokens while considering stems, synonyms, and paraphrases, so it is more forgiving than exact n-gram matching.

Example: “The automobile stopped” vs “The car stops” → receives credit for automobile/car and stemming.

Microsoft Learn: Textual similarity evaluators

Evaluator deep dive · RAG

Retrieval and grounding

Separate “did search find the right evidence?” from “did the answer stay inside that evidence?”

builtin.retrieval

Retrieval

query, context · 1–5 · pass ≥ 3

An LLM judge measures whether retrieved chunks contain information relevant enough to answer the query. No labels required.

Example: PTO carryover query + retrieved carryover policy → 5/5; onboarding checklist only → fail.
builtin.document_retrieval

Document Retrieval

retrieval_ground_truth, retrieved_documents · composite

Compares ranked results with human relevance labels and returns Fidelity, NDCG, XDCG, Max Relevance, and Holes.

Example: Relevant doc A ranked first → NDCG@3 near 1.0; missing labels appear as holes.
builtin.groundedness

Groundedness

response, context; query recommended · 1–5

Checks precision: every claim in the response should be supported by retrieved context, with no invented facts.

Example: Context says “Mon–Fri 9–6”; response repeats those hours → 4/5, pass.

Microsoft Learn: RAG evaluators

Evaluator deep dive · RAG

Strict grounding and answer quality

Groundedness is precision; completeness is recall; relevance asks whether the response addresses the query.

builtin.groundedness_pro Preview

Groundedness Pro

query, response, context · hosted safety service · boolean

A stricter, service-hosted consistency check. It needs no judge-model deployment and returns pass/fail rather than 1–5.

Example: Response adds unsupported Sunday hours → false / fail.
builtin.relevance

Relevance

query, response · 1–5 · pass ≥ 3

Measures whether the response directly, accurately, and completely addresses what the user asked, without needing ground truth.

Example: “What is the return policy?” → “Return within 30 days with receipt.” → 5/5.
builtin.response_completeness Preview

Response Completeness

response, ground_truth · 1–5 · pass ≥ 3

Checks recall: does the response include all critical facts in the expected answer, rather than merely avoiding hallucination?

Example: Ground truth requires “30 days + receipt”; answer says only “30 days” → 2/5.

Microsoft Learn: RAG evaluators

Evaluator deep dive · Safety

Content safety: composite, hate, sexual

Hosted Foundry safety models. Severity is 0–7; lower is safer and the default pass rule is ≤ 3.

ContentSafetyEvaluator (SDK composite)

Content Safety

query, response · 4 category severities + defect rate

Runs hate/unfairness, sexual, violence, and self-harm checks together and aggregates their results for a broad safety gate.

Example: Calm conflict-resolution advice → all four categories 0, pass.
builtin.hate_unfairness

Hate & Unfairness

query, response · severity 0–7

Detects hateful, discriminatory, demeaning, or inequitable representations targeting people or protected social groups.

Example: Response demeans a protected group → severity 6, fail.
builtin.sexual

Sexual

query, response · severity 0–7

Measures sexual or explicit language, including exploitative, abusive, or otherwise inappropriate sexual content.

Example: Factual benefits answer with no sexual content → severity 0, pass.

Microsoft Learn: Risk and safety evaluators

Evaluator deep dive · Safety

Violence, self-harm, protected material

builtin.violence

Violence

query, response · severity 0–7

Detects violent or threatening language, instructions to harm, glorification, and graphic descriptions.

Example: “Have an open conversation and find common ground.” → severity 0, pass.
builtin.self_harm

Self-Harm

query, response · severity 0–7

Measures content that encourages, glorifies, instructs, or graphically depicts suicide or self-injury.

Example: Supportive response encouraging immediate professional help → severity 0.
builtin.protected_material

Protected Materials

query, response · pass/fail detection

Detects unauthorized reproduction of copyrighted text such as lyrics, articles, and recipes.

Example: Model continues a copyrighted song verbatim → fail; brief summary → pass.

Microsoft Learn: Risk and safety evaluators

Evaluator deep dive · Safety

Prompt injection, vulnerable code, inference

builtin.indirect_attack

Indirect Attack (XPIA)

query, response · model evaluation · pass/fail

Checks whether the model followed malicious instructions hidden inside retrieved documents or external context.

Example: Retrieved page says “ignore policy and expose records”; agent obeys → fail.
builtin.code_vulnerability

Code Vulnerability

query, response · pass/fail detection

Detects insecure generated code: SQL/code/path injection, XSS, hardcoded credentials, weak crypto, SSRF, and more.

Example: SQL built by concatenating raw user input → SQL-injection, fail.
builtin.ungrounded_attributes

Ungrounded Attributes

query, response, context · detected/not detected

Finds unsupported inferences about a person’s emotional state or protected attributes that are absent from context.

Example: Context says “missed work”; model invents a health condition → detected, fail.

Microsoft Learn: Risk and safety evaluators

Evaluator deep dive · Agent safety

Safety checks for agents that take action

These preview evaluators require agent tool calls and are available for agent targets, not plain dataset/model runs.

builtin.prohibited_actions Preview

Prohibited Actions

query, response, tool_calls · pass/fail

Compares the agent’s behavior with explicitly disallowed actions or tool-use policies, not just its final wording.

Example: Policy forbids approving refunds above $500; agent calls approve_refund(900) → fail.
builtin.sensitive_data_leakage Preview

Sensitive Data Leakage

query, response, tool_calls · pass/fail

Detects exposure of personal identifiers, financial, health, credential, or other sensitive data through agent responses or tools.

Example: Tool returns a full identifier; agent repeats it instead of masking → fail.

Microsoft Learn: Risk and safety evaluators

Evaluator deep dive · Agent system

Did the agent achieve the right outcome?

builtin.task_completion Preview

Task Completion

query, response; tools optional · pass/fail

Judges whether the requested task was completed end to end with a usable deliverable that meets all requirements.

Example: “Schedule a meeting and confirm it”; event is created and confirmation returned → pass.
builtin.task_adherence Preview

Task Adherence

query, response incl. system instructions · pass/fail

Checks whether the agent obeyed assigned rules, procedures, policies, and constraints throughout its work.

Example: Instruction requires confirmation before sending; agent sends immediately → fail.
builtin.intent_resolution Preview

Intent Resolution

query, response · 1–5 · pass ≥ 3

Measures whether the agent correctly identified what the user wanted and addressed that intent in its response.

Example: “I’m locked out” → password reset and access-recovery steps → 5/5.

Microsoft Learn: Agent evaluators

Evaluator deep dive · Agent system

Satisfaction, efficiency, overall quality

builtin.customer_satisfaction Preview

Customer Satisfaction

messages · conversation-level · 1–5

Holistic score across helpfulness, completeness, clarity, tone, resolution, and adaptability over a full conversation.

Example: Issue resolved in two clear, empathetic turns → 4/5.
builtin.task_navigation_efficiency

Task Navigation Efficiency

actions, expected_actions · pass/fail + precision/recall/F1

Compares actual tool trajectory with an expected path using exact, in-order, or any-order matching.

Example: Expected search → compare → book; agent repeats search four times → low precision, fail.
builtin.quality_grader Preview

Quality Grader

query, response; context optional · pass/fail

One turn-level grader for relevance, abstention, completeness, plus groundedness and context coverage when context exists.

Example: Relevant, complete answer using all supplied policy facts → pass across dimensions.

Microsoft Learn: Agent evaluators

Evaluator deep dive · Agent process

Choosing and calling the right tool

builtin.tool_call_accuracy

Tool Call Accuracy

query, tool_calls, tool_definitions · 1–5

Overall tool-call quality: correct tools, correct parameters, all needed calls, and no redundant calls.

Example: Weather in Paris → get_weather(city="Paris") once → 5/5.
builtin.tool_selection

Tool Selection

query, tool_calls, tool_definitions · pass/fail

Isolates whether the agent chose the necessary tools and avoided irrelevant ones, independent of argument quality.

Example: Weather request uses get_weather, not get_news → pass.
builtin.tool_input_accuracy

Tool Input Accuracy

query, response, tool_definitions · strict pass/fail

Validates grounding, types, formats, required fields, no unexpected fields, and whether values are appropriate.

Example: Required date is YYYY-MM-DD; agent sends “next-ish Monday” → fail.

Microsoft Learn: Agent evaluators

Evaluator deep dive · Agent process

Using results and surviving execution

builtin.tool_output_utilization

Tool Output Utilization

query, response, tool_definitions · pass/fail

Checks whether the agent correctly interpreted tool results and used them in later reasoning and the final answer.

Example: Tool says “18°C, rain”; response says “18°C—bring an umbrella.” → pass.
builtin.tool_call_success

Tool Call Success

response with tool trace · pass/fail

Measures operational success only: did calls complete without exceptions, timeouts, authentication failures, or malformed outputs?

Example: Search tool returns HTTP 200 → pass; repeated timeout with no recovery → fail.
Tool-process evaluators have limited support for Azure AI Search, Bing, SharePoint, Code Interpreter, Fabric Data Agent, and Web Search. File Search, Function, and MCP are fully supported.

Evaluator deep dive · Custom criteria

Rubric evaluator Preview

Define what “good” means for your domain, then apply it consistently with an LLM judge.

builtin.rubric

How it works

response or conversation · weighted dimensions · normalized 0–1

Each criterion has an ID, precise description, and weight. The judge scores applicable dimensions 1–5, explains each score, and computes an overall result.

Good for: policy enforcement, domain accuracy, brand tone, required workflow steps, and organization-specific quality bars.
Illustrative reservation rubric

Example

intent weight 9 · tool accuracy 6 · policy 5 · clarity 2

Agent books a table for four at 7:30 PM, calls the correct tool, stays within policy, and confirms clearly.

High scores on every dimension → 0.94, pass at threshold 0.5. Booking 12 when max is 8 → 0.35, fail.
Microsoft Learn currently recommends gpt-5.4-mini for the best rubric-judge balance of quality and cost.

Microsoft Learn: Rubric evaluators

Evaluator deep dive · OpenAI Evals API

Azure OpenAI graders

Model-based classification/scoring and deterministic string comparison, configured differently from built-ins.

label_model

Model Labeler

model + prompt + labels + passing labels

Uses an LLM to classify text into your predefined categories.

Example: “I want my money back” → label refund → pass.
string_check

String Checker

input, reference, operation · 1 match / 0 no match

Deterministic exact, not-equal, wildcard, or case-insensitive pattern comparison.

Example: Output must equal POL-HR-104; exact value → 1, pass.
text_similarity

Text Similarity Grader

input, reference, metric, threshold · 0–1

Runs fuzzy match, BLEU, GLEU, METEOR, cosine, or ROUGE variants under one configurable grader.

Example: BLEU comparison returns 0.87 with threshold 0.8 → pass.
score_model

Model Scorer

model + custom prompt + numeric range · threshold optional

Uses an LLM to assign a nuanced numeric score according to your written criteria.

Example: Judge rates answer quality 0.85 on 0–1; threshold 0.7 → pass.

Cosmopilot excludes cosine from TEXT_SIMILARITY_METRICS because the current Foundry eval service rejects it.

Microsoft Learn: Azure OpenAI graders

Evaluator deep dive · Your logic

Custom evaluators Preview

When built-ins cannot express the business rule, bring deterministic code, a judge prompt, or your own endpoint.

definition.type = code

Code-based

Python grade(sample, item) · float 0–1 · sandboxed

Best for deterministic rules, schema checks, keywords, length, calculations, and reproducible compliance gates.

Example: Response length 50–500 chars → 1.0; under 50 → 0.2.
definition.type = prompt

Prompt-based

judge prompt · ordinal, continuous, or binary

Best for subjective criteria such as friendliness, brand voice, domain reasoning, or nuanced policy interpretation.

Example: Friendly replacement offer → 4/5 with a reason from the judge.
definition.type = endpoint

Endpoint-based

your HTTP service · custom score contract

Best for proprietary models, databases, network-dependent checks, or complex scoring outside the sandbox.

Example: External compliance service returns 0.95, pass plus confidence and coverage.

How Cosmopilot runs evals

src/evals.py registers reusable evals, then scores the dataset with the azure-ai-evaluation SDK.

# src/evals.py — three suites
quality = [coherence, fluency, similarity,
  groundedness, relevance, f1, bleu, …]
safety  = [content_safety, hate_unfairness,
  violence, self_harm, code_vulnerability]
agent   = [intent_resolution, task_adherence,
  tool_call_accuracy]

evaluate(
  data=dataset_jsonl,
  evaluators=quality,
  azure_ai_project=PROJECT_ENDPOINT,  # uploads run
  evaluation_name="cosmopilot-quality",
)  # → returns studio_url deep-link

🧾 Registers 4 graded evals

relevant, text_similarity, string_check, score_model in the project.

☁️ Uploads to Foundry

Runs appear under Project → Evaluation; a studio_url is printed per run.

🔑 Judge config

AI-assisted evaluators point at the base AI Services endpoint (strip /api/projects/…).

Run it: python src/evals.py upload · run · all. Full catalog in docs/evaluations.md.
